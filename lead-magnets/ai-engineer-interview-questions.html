How to use this: answer each one out loud, on a timer. For every concept, have one definition, one diagnostic ("how would I know this is happening?") and one fix.

1 · ML and deep learning fundamentals

  1. Explain the bias-variance trade-off. How would you diagnose which one your model suffers from?Underfitting vs a train/validation gap; remedies for each; diagnose from learning curves.
  2. What is overfitting and what are three concrete ways to reduce it?Regularization, dropout, early stopping, augmentation, more data. The lever depends on the limit.
  3. How do you split data into train, validation and test sets, and what is data leakage?Role of each split; test touched once; leakage types; one example you caught.
  4. Walk me through gradient descent. Why do people use Adam instead of plain SGD?Update step, learning rate, batch variants; adaptive rates; SGD with momentum can generalize better.
  5. Accuracy is 97%. Why might that be a terrible result?Class imbalance; precision, recall, F1, ROC-AUC, PR-AUC; picking a threshold for the business.
  6. What is an embedding? How would you check whether an embedding model is good for your task?Dense vector where distance reflects meaning; cosine vs dot product; test on your own retrieval set.
  7. Explain attention and why transformers replaced RNNs for sequence tasks.Every token weighs every other; parallel; queries, keys, values; quadratic cost in length.
  8. What is the difference between a generative and a discriminative model?P(y|x) vs the joint or P(x); an example of each; LLMs as autoregressive generators.
  9. How does fine-tuning differ from training from scratch, and when would you do neither?Adapting pretrained weights; "neither" means prompting or retrieval.

2 · LLM and generative AI

  1. When would you use RAG instead of fine-tuning, and when the reverse?RAG for changing, cited or private knowledge; fine-tuning for behaviour, format, style. Not exclusive.
  2. Walk me through a RAG pipeline end to end. Where does quality usually break?Ingest, chunk, embed, index, retrieve, re-rank, assemble, generate, evaluate. Debug retrieval first.
  3. How do you choose a chunking strategy and chunk size?Fixed, recursive, semantic, document-aware; size is tuned against a retrieval eval set.
  4. How would you pick a vector database? Do you even need one?Small corpus: a library or Postgres extension. Then index type, filtering, hybrid search, cost.
  5. What causes hallucination and how do you reduce it in a production system?Unsupported output; better retrieval, abstaining, citations, constrained output; measure faithfulness.
  6. How do you evaluate a RAG system? What metrics would you report?Retrieval metrics vs generation metrics; LLM-as-judge pitfalls; a labeled set before any change.
  7. What is an AI agent, and how does tool calling actually work?LLM in a loop; tool schemas; structured call, execute, feed back; step limits, timeouts, guardrails.
  8. How do you design a prompt you can actually maintain in production?Version it, test on a fixed eval set, structured output, isolate untrusted content.
  9. A longer context window is available. Does that make RAG unnecessary?No: cost, latency, recall loss in the middle, no citations or freshness. They work together.
  10. How do you reduce cost and latency in an LLM application without hurting quality?Model routing, caching, prompt compression, streaming, batching; say how you measure quality.

3 · System design for AI apps — what the interviewer probes

  1. Design a chatbot that answers questions over your company's internal documents.Permissions, chunking, hybrid retrieval, re-ranking, citation, abstaining, eval set, cost per query.
  2. Design an agent that books meetings on behalf of a user across calendars and email.Tool definitions, planning loop, confirmation before irreversible actions, partial failures, audit, limits.
  3. Design a customer-support assistant that must never leak PII or make commitments the company cannot honor.Redaction before the model, input and output guardrails, escalation, red-teaming, safety regressions.
  4. Design a code-review assistant that runs on every pull request for a large engineering org.Queueing, caching identical diffs, context selection, false-positive rate, feedback loop, cost.
  5. Design an LLM-powered search for an e-commerce catalog of millions of products.Hybrid search, latency budget, re-ranking, query understanding, relevance data, index refresh.
  6. You have an existing RAG system whose answers users rate poorly. How would you find out why and fix it?Split retrieval from generation failures; eval set from real logs; fix by measured impact.

4 · Coding round — practical tasks

  1. Implement a retry-with-exponential-backoff wrapper around an LLM API call.Rate-limit vs bad-request errors, capped retries, jitter, idempotency, timeouts.
  2. Parse a document and split it into chunks with a configurable size and overlap.Respect sentence or paragraph boundaries; edge cases; make it testable.
  3. Write a function that computes cosine similarity and returns the top-k most similar vectors.Correct math, zero vectors, when to use a vectorized library or approximate index.
  4. Given a stream of tokens from a model, assemble and validate a JSON object as it arrives.Partial parsing, schema validation, handling malformed output.
  5. Implement a simple rate limiter or token-bucket for outbound API requests.A classic; provider rate limits make it a daily concern.
  6. Deduplicate near-identical documents before indexing.Exact hashing first; embeddings or MinHash for near-duplicates; precision vs cost.

5 · Behavioral and role fit

  1. Tell me about a time a model failed in production. What did you do?Detection, containment, root cause, permanent fix. Own the outcome.
  2. How do you decide between calling a hosted model API and building or hosting your own?Privacy, latency, cost at your volume, fine-tuning needs, lock-in, team capacity.
  3. How do you handle hallucinations when a stakeholder asks you to "just make the model stop lying"?Turn it into a measurable target; explain options, costs and what can be guaranteed.
  4. The field changes every month. How do you decide what to learn and what to ignore?A real system; hands-on tests; name something you evaluated and did not adopt.
  5. Describe a project where you had to ship with imperfect evaluation data.Small golden set, proxies, shipped behind a flag, honest about uncertainty.
  6. Tell me about a disagreement with a product manager or researcher about an AI feature.Resolved with data or a quick experiment; how you explain model limits.
